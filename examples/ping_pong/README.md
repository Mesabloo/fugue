# ping_pong

`PingPongs.tla`: one `Ping` process, a set of `Pong` processes, bouncing
`"Ping"`/`"Pong"` messages. `Ping` receives on shared mailbox `ping`, replies
on per-`Pong` mailbox `pong[from]`; each `Pong` sends to `ping`, receives on
its own `pong[self]`.

## Layout

- `go.mod` — its own Go module (see "Module" below).
- `spec/spec.go` — generated by `fugue compile`, **not** checked in (see `spec/doc.go`'s `.gitignore` entry).
- `ping/main.go` — the `Ping` process, one command.
- `pong/main.go` — a `Pong` process, one command; run once per `Pong`.
- `nameserver/main.go` — the rendezvous point processes register/resolve through.
- `run.sh` — builds and starts one of each above, wired over TCP.

## Module

This directory is its own Go module (`github.com/mesabloo/fugue/examples/ping_pong`), tied to
the repo root's module for its `runtime/*` imports by the root `go.work`. No `replace`
directive is needed — `go build`/`go run`/`go generate` anywhere under the repo root pick up
`go.work` automatically.

## Regenerate

`spec/spec.go` is not checked in, so generate it first:

```bash
go generate ./examples/ping_pong/spec
```

Needs `.lake/build/bin/fugue` built (`lake build fugue`).

## Run

```bash
examples/ping_pong/run.sh
```

Or by hand, in any order (name lookups park until the name appears):

```bash
go run ./examples/ping_pong/nameserver 127.0.0.1:9000
go run ./examples/ping_pong/ping 127.0.0.1:9000 Pong1 Pong2
go run ./examples/ping_pong/pong 127.0.0.1:9000 Pong1
go run ./examples/ping_pong/pong 127.0.0.1:9000 Pong2
```

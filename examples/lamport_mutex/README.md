# lamport_mutex

`LamportMutex.tla`: Lamport's distributed mutual-exclusion algorithm. Every
node runs the same two threads: one requests/holds/releases the critical
section (`ncs`/`try`/`enter`/`cs`/`exit`), the other receives and answers
`request`/`ack`/`release` messages, keeping a Lamport clock and a
priority-ordered request queue (`beats`) so exactly one node enters the
critical section at a time. `CONSTANT`: `Nodes` (a set of `Address`).

Every node's "try" thread multicasts its request to the *whole* `Nodes` set,
itself included — see the comment in `main.go` at `network :=` for what that
means for the wiring.

## Layout

- `go.mod` — its own Go module (see "Module" below).
- `spec/spec.go` — generated by `fugue compile`, **not** checked in (see `spec/doc.go`'s `.gitignore` entry).
- `spec/constants.go` — hand-written CONSTANT `Nodes`, plus `NodeNames`/`ValidNodeName` for
  `main.go`'s `-name` flag.
- `main.go` — the node process; `-name` picks which of `n1`/`n2`/`n3` this process is.
- `nameserver/main.go` — the rendezvous point nodes register/resolve peers through.
- `run.sh` — builds and starts one name server plus `n1`, `n2`, `n3`, wired over TCP.

## Module

This directory is its own Go module (`github.com/mesabloo/fugue/examples/lamport_mutex`),
tied to the repo root's module for its `runtime/*` imports by the root `go.work`. No
`replace` directive is needed — `go build`/`go run`/`go generate` anywhere under the repo
root pick up `go.work` automatically.

## Regenerate

`spec/spec.go` is not checked in, so generate it first:

```bash
go generate ./examples/lamport_mutex/spec
```

Needs `.lake/build/bin/fugue` built (`lake build fugue`).

## Run

```bash
examples/lamport_mutex/run.sh
```

Or by hand, in any order (`Lookup` parks until a peer's name appears):

```bash
go run ./examples/lamport_mutex/nameserver -bind 127.0.0.1:9000
go run ./examples/lamport_mutex -name n1 -bind 127.0.0.1:9101 -ns 127.0.0.1:9000
go run ./examples/lamport_mutex -name n2 -bind 127.0.0.1:9102 -ns 127.0.0.1:9000
go run ./examples/lamport_mutex -name n3 -bind 127.0.0.1:9103 -ns 127.0.0.1:9000
```

Every send/receive is logged (`runtime/debug`'s logging `Sender`/`Receiver`), so a run shows
the `request`/`ack`/`release` traffic and which node holds the critical section.

# paxos

`Paxos.tla`: core of the Paxos consensus algorithm. Every node plays leader,
acceptor, and learner at once — no separate leader-election process; any node
may start a new ballot if it suspects the current leader crashed. `CONSTANT`s:
`N` (node count), `Values` (proposable values), `Nodes` (node addresses),
`MaxRound` (ballot bound, needed to keep the model finite for Go).

## Layout

- `go.mod` — its own Go module (see "Module" below).
- `spec/spec.go` — generated by `fugue compile`, **not** checked in (see `spec/doc.go`'s `.gitignore` entry).
- `spec/constants.go` — hand-written CONSTANTs `Nodes`/`N`/`Values`/`MaxRound` the generated
  file leaves free, plus `NodeNames`/`ValidNodeName` for `main.go`'s `-name` flag.
- `main.go` — the node process; `-name` picks which of `n1`/`n2`/`n3` this process is.
- `nameserver/main.go` — the rendezvous point nodes register/resolve peers through.
- `run.sh` — builds and starts one name server plus `n1`, `n2`, `n3`, wired over TCP.

## Module

This directory is its own Go module (`github.com/mesabloo/fugue/examples/paxos`), tied to the
repo root's module for its `runtime/*` imports by the root `go.work`. No `replace` directive is
needed — `go build`/`go run`/`go generate` anywhere under the repo root pick up `go.work`
automatically.

## Regenerate

`spec/spec.go` is not checked in, so generate it first:

```bash
go generate ./examples/paxos/spec
```

Needs `.lake/build/bin/fugue` built (`lake build fugue`).

## Run

```bash
examples/paxos/run.sh
```

Or by hand, in any order (`Lookup` parks until a peer's name appears):

```bash
go run ./examples/paxos/nameserver -bind 127.0.0.1:9000
go run ./examples/paxos -name n1 -bind 127.0.0.1:9101 -ns 127.0.0.1:9000
go run ./examples/paxos -name n2 -bind 127.0.0.1:9102 -ns 127.0.0.1:9000
go run ./examples/paxos -name n3 -bind 127.0.0.1:9103 -ns 127.0.0.1:9000
```

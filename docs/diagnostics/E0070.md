# E0070: undefined macro

A `Name(e₁, …, eₙ);` call names no declared `macro`.

`Identifier(args);` is parsed as a macro call regardless of whether `Identifier` is actually
declared as one (there is no other statement shape it could be, given PlusCal's own grammar), so
this is only caught once expansion looks the name up.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    process (P = PID) {
    p1: Foo(1);
        goto Done;
    }
}*)
====
```

No `macro Foo(...) { ... }` is declared anywhere in the algorithm.

## How to fix it

- Declare the macro before the algorithm's processes, or fix a typo in the name.
- If a plain assignment was intended, `Foo` cannot be used with `(...)` syntax that way — assign
  to it directly instead.

# E0072: macro argument not assignable

A macro's body writes to one of its parameters (as an `assign` target, a `receive`'s channel or
target, or a `send`'s channel), but the actual argument at this call site is not itself a
reference (a variable, optionally indexed or field-accessed) that anything could be written back
to.

Passing a variable by name into a macro that writes to its parameter is a real, common PlusCal
idiom — the macro's parameter stands for whatever reference expression the caller passed, exactly
as if the body had been pasted in with the parameter replaced by the argument's own text. That
only makes sense when the argument is itself a writable reference.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    macro Inc(v) {
        v := v + 1;
    }
    process (P = PID) {
    p1: Inc(3);
        goto Done;
    }
}*)
====
```

`Inc`'s body assigns to `v`, but `3` is not a reference — there is nowhere to write the result.
The `note:` points at the assignment inside `Inc`'s own body that requires this.

## How to fix it

- Pass a variable (optionally indexed/field-accessed) instead: `Inc(counter)`, `Inc(arr[k])`.
- If the macro is only meant to read its parameter, check its body doesn't also assign to it.

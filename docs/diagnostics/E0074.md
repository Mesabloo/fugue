# E0074: name already declared

A `CONSTANT`, `VARIABLE`, operator, or function declaration names something already bound in this
module — either a previous declaration under the same name, or a name with a fixed, built-in
meaning (an intrinsic operator, or a name an `EXTENDS`-ed module already provides).

## Why it fires

```tla
---- MODULE Example ----
CONSTANT X
X == 5
====
```

`X` is declared twice: once as a `CONSTANT`, once as an operator. The second declaration silently
overwriting the first would make which one a reference to `X` actually means depend on where the
reference sits, so it's rejected instead.

This also fires for a name that collides with something already fixed by the language or an
`EXTENDS`-ed module — for example `CONSTANT _+_` in a module that `EXTENDS Naturals`, which already
gives `+` its own meaning.

## How to fix it

- Rename one of the two declarations.
- If the collision is with an `EXTENDS`-ed module's own operator, rename the local one instead —
  redefining it is not supported.

# E0073: unexpanded macro call reached desugaring

A compiler bug, not a problem with your specification.

Every `macro` call is rewritten away by the expansion pass, the very first step of statement
desugaring. A `.macroCall` reaching statement desugaring itself means expansion did not run, or
ran and missed one — a well-formed program that passed parsing should never reach it.

## Why it fires

Expansion's own guarantee (every macro call is gone before the rest of desugaring runs) did not
hold. The message names the call site.

## How to fix it

- Report it, with the module you were compiling and the full message text.

## See also

- `E0056` — the same kind of internal-invariant check, in a later pass.

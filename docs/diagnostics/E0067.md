# E0067: duplicate macro declaration

Two `macro` declarations in the same algorithm share a name.

A macro name has to be unique across the whole algorithm, the same way a process name does —
there is no scoping that could make two same-named macros unambiguous at a call site.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    macro Foo() {
        skip;
    }
    macro Foo() {
        skip;
    }
    process (P = PID) {
    p1: skip;
        goto Done;
    }
}*)
====
```

Both macros are named `Foo`.

## How to fix it

- Rename one of the two macros.
- If the two bodies are meant to be the same thing, delete the duplicate.

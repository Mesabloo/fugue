# E0077: used at two incompatible types

A value is used in two places that demand types with nothing in common: no type is a subtype of
both, so no single type for the value satisfies every use.

This comes up when a definition has no `@type` and its type is worked out from its body. Each use
of a parameter says the widest type it may have; the parameter gets the tightest of these. Two uses
that disagree outright — one needs an `Int`, the other a `Bool` — leave no type to pick.

## Why it fires

```tla
---- MODULE Example ----
EXTENDS Naturals

Bad(x) == x + 1 > 0 /\ x
====
```

`x + 1` needs `x` to be an `Int`; `... /\ x` needs it to be a `Bool`.

## How to fix it

- If one use is a mistake, correct it.
- Otherwise give the definition a `@type`, so the type checker reports the exact use that does not
  fit it.

- `E0043` — a type that nothing constrains at all.

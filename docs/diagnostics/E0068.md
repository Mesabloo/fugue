# E0068: label inside macro body

A label appears inside a `macro` body.

Real PlusCal forbids this outright, at any nesting depth: a macro is expanded by pure textual
substitution at every call site, so a label inside one would either have to be duplicated across
every call site (breaking the "one label, one block" invariant every other label in the algorithm
relies on) or renamed per call site (which macros never do — they are non-hygienic). Neither is
sound, so it is simply not allowed.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    macro Foo() {
        oops: skip;
    }
    process (P = PID) {
    p1: skip;
        goto Done;
    }
}*)
====
```

`Foo`'s body contains the label `oops:`.

## How to fix it

- Move the labelled code out of the macro and into the calling process directly.
- If the macro is meant to control flow across an atomic-step boundary, it cannot be a macro —
  write it out by hand at each call site instead.

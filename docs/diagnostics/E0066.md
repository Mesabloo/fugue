# E0066: duplicate label

Two blocks of one algorithm carry the same label.

Labels are one flat namespace shared by every process — not scoped per process — matching the
original PlusCal-to-TLA+ translator, where each label becomes its own top-level TLA+ definition.
Two processes reusing a name collide there even though a `goto` in either one could only ever
reach its own process's blocks.

Within a single process a duplicate is also an operational hazard on top of that: a label denotes
the union of every block carrying it, so a `goto` to it would silently become a non-deterministic
choice between them rather than the sequential program the source text reads as.

## Why it fires

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID1,
    \* @type: Address;
    PID2

(*--algorithm Example {
    process (P1 = PID1)
        variables x = 0;
    {
    p1: x := 1;
    }

    process (P2 = PID2)
        variables y = 0;
    {
    p1: y := 1;
    }
}*)
====
```

Both processes define a `p1:` block.

## How to fix it

- Rename one of the labels — pick something unique across the whole algorithm.
- Reusing a naming scheme across processes (`p1`, `p2`, …) has to be varied per process, e.g.
  `p1_send`/`p1_recv`.

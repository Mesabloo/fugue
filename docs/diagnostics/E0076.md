# E0076: RECURSIVE annotation mismatch

An operator's `RECURSIVE` declaration gives it a type, and its later `==` definition repeats the
`@type` annotation with a different one. The two are required to agree.

## Why it fires

```tla
---- MODULE Example ----
RECURSIVE
    \* @type: Int => Int;
    F(_)

\* @type: Int => Str;
F(x) == "x"
====
```

`F` is predeclared with type `(Int) => Int`, but its definition annotates it `(Int) => Str`
instead.

## How to fix it

- Make the definition's `@type` match the `RECURSIVE` declaration's, or
- Drop the definition's `@type` entirely — it is optional once `RECURSIVE` already gives the
  operator a type, and the definition is then checked against that type directly.

## See also

- `W0009` — the same annotation repeated with no disagreement is redundant, not an error.
- `E0075` — the predeclared operator has no definition at all.

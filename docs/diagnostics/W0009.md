# W0009: redundant RECURSIVE annotation

An operator definition carries its own `@type` annotation, but the operator was already given
that exact type by an earlier `RECURSIVE` declaration. The annotation adds nothing.

## Why it fires

```tla
---- MODULE Example ----
RECURSIVE
    \* @type: Int => Int;
    F(_)

\* @type: Int => Int;
F(x) == x
====
```

`F`'s `RECURSIVE` declaration already fixes its type as `(Int) => Int`; repeating the identical
`@type` on the definition is accepted but redundant.

## How to fix it

- Drop the definition's `@type` — the operator is already checked against the type its
  `RECURSIVE` declaration gave it.
- Silence with `-Wno-redundant-recursive-annotation` if keeping the annotation is preferred, for
  example to keep every definition self-documenting.

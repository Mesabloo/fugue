# E0069: recursive macro

A macro is defined, directly or indirectly, in terms of itself.

Real PlusCal macros are pure textual substitution: expanding a call splices in the macro's body
with its parameters replaced. A macro that (directly, or through a chain of other macros) calls
itself would expand forever, so this is checked and rejected before any expansion is attempted.

## Why it fires

Direct self-call:

```tla
---- MODULE Example ----
CONSTANTS
    \* @type: Address;
    PID

(*--algorithm Example {
    macro Foo() {
        Foo();
    }
    process (P = PID) {
    p1: skip;
        goto Done;
    }
}*)
====
```

Or a cycle through another macro:

```tla
(*--algorithm Example {
    macro A() { B(); }
    macro B() { A(); }
    ...
}*)
```

The error points at the macro whose declaration the cycle was found from; a `note:` for each call
in the cycle traces the loop back to it, in order.

## How to fix it

- Break the cycle: inline one of the calls instead of routing through another macro.
- A macro calling a *different*, non-cyclic chain of other macros is fine — only an actual loop
  in the call graph is rejected.
